# Assignment I — Rubric-to-Evidence Mapping

This document maps every requirement of **AIMLCZG549 Assignment I** (10 marks Data Pipeline + 5 marks API Access) to concrete files, commands, endpoints, and screenshots.

## Sub-Objective 1: Design and Development of a Data Pipeline (10 Marks)

| Rubric Item | Implementation & Evidence | Commands / Endpoints / Expected Screenshots |
|---|---|---|
| **1.1 Business Understanding** — Identify a data science business problem | Telco customer churn prediction so retention teams can prioritize at-risk subscribers and reduce revenue loss. Documented in [README.md](../README.md#1-business-case--dataset) and generated model card (`artifacts/runs/<run_id>/<run_id>_model_card.md`). | `make run-once` generates `<run_id>_model_card.md` |
| **1.2 Data Ingestion** — Public dataset with sufficient records, validation, provenance | [src/telco_churn_dataops/ingestion.py](../src/telco_churn_dataops/ingestion.py): downloads IBM Telco Customer Churn CSV (`7,043` rows, `21` columns) from `DATASET_URL` with timeout, HTTP/content-type/schema/min-row validation, atomic idempotent save to `data/raw/telco_churn_<run_id>.csv`, and SHA-256 checksum recorded in `manifest.json`. | `make run-once`; `GET /api/v1/runs/latest` (`ingestion` block); unit tests in [tests/test_pipeline.py](../tests/test_pipeline.py) |
| **1.3 Data Pre-processing** — Summary stats, missing values, numeric imputation, dtypes, normalization, leakage-free split | [src/telco_churn_dataops/preprocessing.py](../src/telco_churn_dataops/preprocessing.py): converts blank `TotalCharges` strings (`11` rows) to `NaN`/float; emits before/after quality report, dtypes, duplicate count, missing-value CSVs, numeric/categorical summaries; stratified train/test split (`test_size=0.2`, `seed=42`, `customerID` excluded); sklearn `ColumnTransformer` with training-only median numeric imputation + `StandardScaler` and mode categorical imputation + `OneHotEncoder`. | `artifacts/runs/<run_id>/<run_id>_preprocessing_report.json`, `*_numeric_summary.csv`, `*_missing_values_*.csv`; Dashboard **Data quality** tab (`docs/screenshots/dashboard_local.png`) |
| **1.4 Exploratory Data Analysis (EDA)** — Correlations, categorical relationships, binning, encoding, feature importance, univariate/bivariate charts | [src/telco_churn_dataops/eda.py](../src/telco_churn_dataops/eda.py) & [src/telco_churn_dataops/modeling.py](../src/telco_churn_dataops/modeling.py): generates 10 run-scoped PNG charts + CSV/JSON summaries — target distribution, numeric histograms & boxplots, categorical churn rates, Pearson correlation heatmap, bias-corrected Cramer's V, tenure bins (`0-12m`..`61-72m`), monthly-charge quartiles, contract x tenure heatmap, confusion matrices, and test-set permutation feature importance (ROC-AUC drop). Encoding & scaling evidence saved in `transformation_evidence`. | `GET /api/v1/eda/latest`; `GET /api/v1/metrics/latest`; Dashboard **EDA** and **Model metrics** tabs; `artifacts/runs/<run_id>/<run_id>_*.png` |
| **1.4+ Machine Learning & Model Card** — Compare classifiers, select champion, persist artifacts | [src/telco_churn_dataops/modeling.py](../src/telco_churn_dataops/modeling.py): compares `LogisticRegression` (test ROC-AUC `0.8413`, CV `0.8459 ± 0.0124`) vs `RandomForestClassifier` (test ROC-AUC `0.8399`, CV `0.8453 ± 0.0095`) under the identical preprocessing pipeline; persists champion `champion.joblib`, `champion_metadata.json`, and `<run_id>_model_card.md`. | `GET /api/v1/metrics/latest`; `POST /api/v1/predictions` |
| **1.5 DataOps** — Automated workflow every 2 minutes, structured logging, monitoring/drift, cloud dashboard | [src/telco_churn_dataops/flows.py](../src/telco_churn_dataops/flows.py), [src/telco_churn_dataops/monitoring.py](../src/telco_churn_dataops/monitoring.py), [prefect.yaml](../prefect.yaml), [src/telco_churn_dataops/dashboard/app.py](../src/telco_churn_dataops/dashboard/app.py): named Prefect flow `telco-churn-pipeline` and deployment `telco-churn-every-2-min` with `IntervalSchedule(interval=120)`. Transient network retries (`3x`), structured JSONL logs (`run_log.jsonl`), Prefect table/markdown artifacts, quality + drift checks (`PASS`/`WARN`/`FAIL`) against previous successful run, plus Streamlit dashboard & Prefect UI/Cloud dashboard. | `make prefect-server`, `make deploy-local`, `make worker`; Prefect Cloud steps in [docs/DEPLOYMENT.md](DEPLOYMENT.md); local screenshots `docs/screenshots/prefect_deployment_local.png` and `docs/screenshots/dashboard_local.png` (capture cloud equivalents after connecting Prefect Cloud) |

## Sub-Objective 2: API Access (5 Marks)

| Rubric Item | Implementation & Evidence | Commands / Endpoints / Expected Screenshots |
|---|---|---|
| **3.1 Retrieve Key Application Details** — Built-in orchestration APIs | [src/telco_churn_dataops/prefect_adapter.py](../src/telco_churn_dataops/prefect_adapter.py): uses `prefect.client.orchestration.PrefectClient` configured via `PREFECT_API_URL` and optional `PREFECT_API_KEY` to call `GET /flows/{id}`, `GET /deployments/name/{flow}/{deployment}`, `POST /flow_runs/filter`, `GET /work_pools/{name}`, and `POST /work_pools/{name}/workers/filter`. | `GET /api/v1/application-details`; mocked success/failure unit tests in [tests/test_api.py](../tests/test_api.py) |
| **3.2 Display Application Details** — At least 4 retrieved details | `GET /api/v1/application-details` presents **5+ real details** with source endpoints and `retrieved_at`: (1) `flow` (ID, name, created), (2) `deployment` (ID, name, entrypoint, status, 120s `IntervalSchedule`), (3) `latest_flow_run` (ID, name, state, start/end timestamps, duration), (4) `work_pool` & `workers` (ID, name, type, status, online workers & heartbeat), plus (5) `next_scheduled_run` and `recent_flow_runs`. Returns transparent `503` if Prefect is unreachable. | `curl -s http://127.0.0.1:8000/api/v1/application-details`; local screenshot `docs/screenshots/api_application_details_local.png` |
| **3.3 API Testing and Documentation** — Client tests, status codes, sample requests/responses, screenshots | [docs/API_TESTING.md](API_TESTING.md), OpenAPI Swagger UI (`/docs`), [postman/Telco-Churn-DataOps.postman_collection.json](../postman/Telco-Churn-DataOps.postman_collection.json), and automated FastAPI test suite ([tests/test_api.py](../tests/test_api.py)). Covers `200` health, `200` application details, `200` valid prediction, `422` invalid prediction, `404` missing manifest, and `503` Prefect unavailable. | `make test`; Swagger UI screenshot `docs/screenshots/swagger_api_local.png`; error screenshot `docs/screenshots/api_error_503_local.png` |
